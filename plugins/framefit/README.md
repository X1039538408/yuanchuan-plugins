# 视频套版 FrameFit

把视频发到 Codex，用一句话完成横竖转换和模板套版。视频在使用者自己的 Windows 64 位电脑处理；共享功能、面板、模板与预设通过 GitHub 稳定版本同步。

## 安装与使用

在 Codex「插件 → 添加插件市场」中添加 `X1039538408/yuanchuan-plugins`，Git 引用选择 `main`，稀疏路径留空。安装 **视频套版 FrameFit**，在新聊天中用 `@` 选择它。

首次使用需要联网下载 Windows 便携运行包；以后准备新任务时检查稳定版本。有已验证的缓存时，更新失败可以继续使用缓存版，实际版本与警告会显示在工具结果中。维护者必须先发布 Release 并合并稳定清单，插件才能在其他电脑完成首次启动。

使用者无需安装原软件、Python、Node.js 或 FFmpeg，无需登录 GitHub 或媒体服务，不收插件使用费。需要已安装且支持本地 MCP／插件的 Codex；Codex 自身的账号和使用额度遵循用户已有服务。设备需保持开机，具备输入读取与输出写入权限；首次下载及版本检查需能访问 GitHub、raw.githubusercontent.com 和 GitHub Release 下载地址。

```text
@视频套版 把这些视频套用内置横版模板，1080P，高画质，保留原声，直接导出。
@视频套版 打开配置面板，我想选择模板、调整窗口并预览第 3 秒。
@视频套版 用 D:\模板\品牌.png 套版，完整显示，输出到 D:\成片。
@视频套版 取消刚才的任务。保留完成的视频，之后继续剩下的。
```

附件必须能在当前电脑以真实文件路径读取。宿主没有提供可访问路径时，请提供本机视频／文件夹完整路径。面板也可每行填一个路径；不会假装网页文件选择器能够读取本机路径。

## 支持功能

| 项目 | 选项 |
| --- | --- |
| 转换 | 竖转横、横转竖、自定义模板比例 |
| 模板 | 内置横版／竖版、自选图片 |
| 窗口 | 自动、透明、黑色、白色识别；手动 `[x,y,宽,高]` |
| 适配 | 等比填满、完整显示、拉伸、10%～500% 自由缩放 |
| 预览 | 指定视频与秒数的合成静帧 |
| 导出 | 720P、1080P、4K、模板原始尺寸；高／标准画质 |
| 编码 | 自动优先 NVIDIA、强制 NVIDIA、CPU |
| 队列 | 逐条进度、失败详情、取消、继续、打开输出 |
| 预设 | 稳定版本共享预设、本机个人预设 |

视频叠在模板上方。放大后可以覆盖模板装饰，只在成片边界裁切；识别窗口用于定位与适配。原视频有声音则保留音轨，无声输入保持无声。同名输出自动编号。

自动编码在 NVIDIA 不可用或编码失败时回退 CPU；强制 NVIDIA 会明确报错。不同电脑的驱动、显卡和视频编码支持会影响速度与可用性。预览可核对布局，实际编码结果以导出任务为准。

对话与面板使用相同会话配置。点击预览／导出会保存面板参数；导出时冻结版本与参数，后续调整用于下一次任务。用户已经明确要求导出时，Codex 可以直接处理，不需要先打开面板。

## 更新、数据与卸载

有两类更新：

- **处理程序、面板和共享资源**：准备新任务时检查 `channels/stable.json`，下载 Release 包，校验 SHA-256 和文件清单后切换版本。运行中的任务固定原版本；更新失败保留可验证的缓存版。
- **插件技能、名称、工具接口及启动器**：在 Codex 刷新／升级市场；必要时重启并新建聊天。`@` 调用本身不会绕过首次安装或市场刷新要求。[官方插件说明](https://developers.openai.com/plugins/build/plugins)

本机数据默认位于 `%LOCALAPPDATA%\FrameFitCodex`，包含运行版本、个人配置、预设和任务记录。个人路径、视频与日志不上传。版本下载会向 GitHub 发起普通公开请求；源码仓库和 Release 中的共享资源是公开内容，不应包含私人素材或机器路径。

在 Codex 卸载插件后，如需清理缓存，可手动删除上述本机数据目录。导出视频位于配置的输出目录，另行管理。共享版本不会覆盖个人预设。

## 维护与发布

维护者需要 GitHub 仓库写入权限，使用者只需要公开下载权限。遵循仓库 [贡献指南](../../CONTRIBUTING.md)，通过 PR 修改 `plugins/framefit` 的处理程序、面板、共享模板和预设，不覆盖其他插件。

1. 更新处理版本，并同步插件两个 manifest（若技能／接口也变更）；本机运行相应测试。
2. 通过 PR 审核合并源码，创建 `framefit-v1.0.0` 格式的版本 tag，或手动运行 `.github/workflows/framefit-release.yml` 并填写版本。
3. 工作流在 Windows 构建并验证 `framefit-<版本>-windows-x64.zip`，上传 GitHub Release，然后创建稳定清单 PR。
4. 审核并合并 `codex/framefit-channel-<版本>` 的稳定清单 PR。此时其他电脑下次准备任务获取该稳定版；仅上传 Release 尚未激活稳定版。

需要本机打包时，在 Windows x64 构建环境安装 `requirements-build.txt`，准备 FFmpeg／FFprobe 及其许可证和对应源码来源，然后运行：

```powershell
python plugins/framefit/tools/build_release.py --version 1.0.0 --ffmpeg-dir D:\media-build --output dist\framefit
```

构建端需要 Python 和构建依赖，使用端不需要。构建输出为 ZIP、SHA-256、运行文件清单与稳定清单；ZIP 包含宿主、处理程序、Python 运行依赖、媒体工具、面板、模板、共享预设和许可。不要提交整个便携包到 Git；使用 GitHub Releases。

运行目录按版本独立保存，启动器默认固定使用公开稳定清单地址。下载失败或校验失败时不会替换已验证版本；首次下载失败则需恢复网络后重试。旧任务恢复使用原版本；不将中断任务静默改到新版本。

## 开发验证

```powershell
node --test plugins/framefit/tests/panel_contract.test.mjs
$env:FRAMEFIT_BIN_DIR = 'D:\media-build\bin'
python -m pytest plugins/framefit/tests -q
```

Node 仅用于开发面板测试。测试覆盖与发布记录应区分：桥接／处理／更新器自动化验证、便携包启动验证、真实 Codex 面板与附件验收，以及独立干净电脑首次安装验收。自动化测试通过不能代替未执行的宿主或跨电脑验证。
