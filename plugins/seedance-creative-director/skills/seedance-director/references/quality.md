# 交付前检查

检查内容本身，不向用户输出完整检查清单。

1. 当前是否还有决定动机、关键因果、身份、能力或结局的待决问题？有则先沟通，不能把未回答的方向当定稿。
2. 是否遵守用户最新明确修改，并保留其他已确认内容？是否误把主动补全升级为用户要求？
3. 宫格模式是否得到明确确认？未确认时是否只推荐而没有生图或切换流程？
4. 宫格生图是否已确认画幅比例和分辨率？未确认时是否停止在询问阶段？是否使用 LibTV 普通图片模型而非宫格快捷预设？是否优先核对 MCP 插件授权，而不是误读本地 CLI 401？
5. 图像是否实际查看？观察事实、用户文字和创作补充分清了吗？未看见的素材不假装已读取。
5. 动作路径、接触、手部占用、数量和终点是否一致？关键结果是否有可见证据？切镜或跳时是否交代清楚？
6. 如果已生成宫格图，是否已经暂停等待用户验收？是否重新核对每格和格间状态？
7. 机位、视角、焦点、运动与剪辑是否相容？固定机位、一镜到底等只在适用范围执行。
8. 是否遵守指定台词与声音要求？动作和对白能否在时长内自然完成？
9. 原有像素/动漫/写实等风格是否被不相关质量词覆盖？是否添加了无关人物、道具或电影情节？
10. 素材映射是否真实、唯一、稳定？LibTV 的每个引用是否符合[固定语法](adapters/platforms.md)，保留双层花括号、`Mixed` 后一个半角空格与本轮原始素材序号，且图片、视频、音频统一编号？双平台版本是否仅引用语法不同？未知参数是否被错误承诺？
11. 最终正文是否完整、中文清楚、指代明确，并去掉无关负向词和重复规则？讨论选项是否混进最终画面指令？
12. 本轮是否属于“继续/恢复”而非新修改？若上一轮已经交付同一份完整双版本，是否避免重复粘贴；若只完成一版，是否只补缺失版；若有新修改，是否只重算受影响内容并保持其余确认内容？
13. 上一轮是否发生流式断开或响应解码失败？若发生，是否把已经可见内容视为已发送，只从可识别断点继续；无法识别断点时是否先说明并询问重发，而不是盲目重放长提示词？
14. 双版本提示词完成后是否询问用户是否使用 LibTV 生成视频？用户选择“否”时是否没有调用视频工具？
15. 用户选择“是”后是否交给视频生成流程控制器，而不是让模型自行推断固定流程？
15a. 控制器是否先检查 profile，再优先筛选 DH `folderId` 中按更新时间排序的最近 6 个项目，并让用户选择精确项目 UUID？如果没有可靠 DH `folderId`，是否先询问而不是猜测？
15b. 如果 LibTV 返回多个账号/团队，是否先显示账号名、套餐标识和当前激活状态？是否明确区分套餐额度与剩余积分，并在没有余额接口时标注暂不可读取？
15c. 需要独立多账号时是否确保所有 CLI 命令使用所选 profile 的 `LIBTV_CONFIG_DIR`？是否避免把远程 MCP 当前 OAuth 会话误当成所选 profile？
16. 正式生成前是否通过控制器展示完整参数和素材摘要并获得最终确认？不支持的组合是否严格拦截而没有自动替换？
17. 模型目录和 schema 是否运行时读取？新模型是否可以自动进入列表？未知必填字段是否严格拦截？
18. 是否使用 LibTV 版 prompt 和真实 image/video/audio 节点；是否避免把 `{{Mixed N}}`、文件名或宫格格号当作节点 ID？
19. 是否先执行控制器本地 schema 预检，再只提交一次视频节点 `--run`？断线或“继续”是否只恢复原 run 状态和 node/task 身份，没有重复提交或重复扣费？
20. 用户选择即梦 CLI 时，是否先区分即梦画布和即梦对话，并使用对应的项目/节点或 session/submit_id？
21. 即梦账号是否只选择一次并在任务内复用？画布 profile 是否与对话 CLI 隔离？画布登录是否没有被误报为对话登录？
22. 即梦画布项目是否按更新时间展示最近 6 个并要求精确 UUID？即梦对话是否展示最近 6 个 session，并明确标注默认对话？
23. 即梦对话是否先读取 `user_credit` 和目标子命令帮助？0 积分是否保留为真实值，缺失余额是否标注暂不可读取？
24. 即梦提交是否取得真实 `submit_id` 或 `operationRef` 才报告已提交？“继续”是否只查询原身份，没有重新生成？
25. 宿主支持右侧控制面板时，是否一次调用批量预检并展示全部实时选项，而不是把固定参数拆成多轮聊天？
26. 面板默认值是否标明自动填充且可修改？最近 6 个项目/会话是否只是首屏列表，并保留刷新或搜索全部入口？
27. 面板是否在用户点击“确认并生成”前只执行读取和预检，没有创建付费任务？是否只提交一次并保存原任务身份？
28. 切换平台、账号、适配器或模型时，是否只刷新受影响字段？“继续”是否只查询原 `operationRef` 或 `submit_id`？

发现模型自行添加的冲突时直接修正。发现用户核心要求不能兼容时提问；不要默默丢弃其中一项。修正后只重查受影响内容，避免无止境重写。
