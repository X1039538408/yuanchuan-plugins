# 动作状态与可见结果

## 适用

拿放、开合、收纳、交接、穿戴、攻击、修理、形态或数量变化，以及连续事件跨镜头。

## 规则

内部维护最小状态链：角色位置、关键手部占用、道具位置与数量、门/容器开合、已完成动作、镜头结束状态。只记录影响本次事件的对象，不生成全场景数据库。

每个关键动作需要起始状态、路径或接触关系、可见变化、结束状态。完成证据应可见，如剑完全入鞘、手松开杯子、箱盖合拢；“成功完成”不能代替证据。

先后依赖用动作顺序表达，不能把放下、关盖、提起、离开塞进同一瞬间。双手被占用时，要先换手、放下或交接；不过度指定不影响结果的每根手指。

同一连续事件切镜后继承上镜结果。全局规则不重复堆叠，但新镜头允许简短重申仍关键的状态。

用户明确指定的时间跳跃、剪辑省略、法术移动或超现实变化，按其世界规则处理；重点检查故事内部一致性，不套用现实主义否定它们。

因果缺口涉及“道具如何获得、死者为何复活、角色如何知道秘密”等，不能靠补一个动作遮盖，转入 [共创澄清](../dialogue.md)。

动作与指定时长不匹配时先减少未要求的装饰细节。关键事件仍无法自然完成时，讨论延长时长、拆镜或省略范围，不以压缩文案假装解决。

## 输出与例子

输出连续动作安排和需要镜头呈现的关键证据，不展示内部状态表。

“装盒并离开”：物体进入盒内、手离开、盒盖关闭、拿起盒子再离开。用户只要求放入，不自动添加关盒和离开。

“左手拿灯、右手持剑，双手推开重门”：可先安排收剑或放灯；若用户要求两件道具始终不松手且必须双手推门，先问取舍。
