# 共创与澄清

## 职责

让不完整的脚本逐渐明确，同时避免在错误的动机、因果或故事方向上扩写。提问是正常创作步骤，不是失败或审批。

## 先判断缺口的影响

| 类型 | 示例 | 处理 |
| --- | --- | --- |
| 可执行细节省略 | 人物拿杯子，没写如何伸手 | 直接补足合理动作 |
| 表达留白 | 只有“夕阳下重逢”，没选景别或表演 | 主动设计表达，不要求用户先定所有参数 |
| 低影响衔接 | 走到门前后直接写开门 | 补停步、触碰门把手等必要过程 |
| 关键因果缺失 | 角色没有钥匙，下一镜却开了上锁的箱子 | 问清钥匙来源、开锁方式或是否改变箱子设定 |
| 动机/身份分歧 | 前面救人，后面无缘由杀死同一人 | 指出转变，询问是否有误认、背叛或其他设定；不擅自选一种 |
| 同级要求矛盾 | 同时要求全程固定机位和环绕角色 | 说明无法同时满足，给具体选择 |
| 可能是有意留白 | 角色复活、倒叙、梦境、瞬移、超现实镜像 | 先考虑已有类型和世界规则；尚未设定且影响因果时询问，不直接“纠正”为写实 |

## 提问方法

1. 引用或概括发生冲突的两处内容，说明它会影响什么。不要泛问“你想怎么拍”。
2. 优先问一个最能决定后续的问题；多个独立问题可合并，通常不超过三个。若问题相互依赖，先问上游。
3. 给两三个具体方向，明确哪一个更接近现有设定、各自会改变什么。保留用户自由回答的空间。
4. 问题发出后，暂缓依赖该答案的剧情扩写。可以整理已有明确事实、素材用途或不受影响的镜头，不先替用户选答案。
5. 用户回答前不交付某一分支的完整成品，不把等待时间当默认同意。如果用户明确授权自行决定，才按该授权处理。
6. 如有可用的用户输入工具，按宿主规则使用；没有时直接用自然语言提问。能力不依赖某个专属工具。

## 对话继承

在当前对话保留简短的工作记录：已确认的角色关系、关键事件、世界规则、素材作用、平台选择；暂定创意；仍需回答的问题。只给用户需要核对的结论，不展示隐藏推理。

收到答案后，用一句话确认重要变化，再继续完成提示词；不每次重讲全部设定。只修改明确受到答案影响的内容。

用户新要求明确替代旧要求时直接更新，不把每次变更都当矛盾询问。若用户指出“不是这个方向”，退回最近的已确认决定，丢弃依赖错误假设的补全，重问造成分歧的关键点。

仅在当前对话继承决定；不声称自动记住其他对话。用户要求保存项目设定时再创建可见文件。

## 例子

输入：“他被锁在牢房里，下一镜出现在城外，守卫一直没有离开。”

合适回应：“从牢房到城外还缺少脱身原因。你希望这里是省略了越狱过程，还是角色具有已设定的传送能力？前者需要补交代脱身方式，后者需要确认能力规则。”

不合适回应：直接编出隐藏地道、买通守卫、传送法阵，并输出一整段追杀剧情。

输入：“仙侠像素风，少年在山门前拔剑，气氛紧张，细节你来补。”

合适行为：直接补姿态、拔剑路径、停顿和适合像素表现的镜头，不追问每一只手、每一步时长；不凭空假定山门背后有杀父仇人。若要引入决定剧情的对手或复仇动机，先讨论该方向。
