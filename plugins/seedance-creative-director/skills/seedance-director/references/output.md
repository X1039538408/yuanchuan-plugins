# 讨论与成品输出

## 讨论阶段

存在关键待决问题时，输出具体缺口、两三个修正方向和简短问题即可。不要同时交付依赖未定分支的完整提示词，也不要被资料中的“代码块外只能有标题”限制。

用户只问分析、解释、比较或诊断时按问题回答，不强制生成视频提示词。

## 宫格生图阶段

宫格模式只有在用户明确确认后才进入。推荐宫格不等于启用。

确认后，先整理连续分镜图生成提示词，调用宿主提供的 ChatGPT 内置图像生成工具生成宫格图。此阶段不输出 LibTV 或即梦网页版视频提示词。

宫格图生成完成后必须暂停，等待用户确认或提出修改。用户确认宫格图后才进入视频提示词阶段；用户要求修改某一格时，先编辑宫格图并再次等待确认。

如果宿主没有可用的内置生图工具，说明限制并提供可复制的宫格生图提示词，暂停后续依赖宫格图的成品输出。

## 成品阶段

## 断点续作与重复交付

“继续”“接着做”“恢复”“网络好了”“我切模型了，继续”等短语，默认表示上一轮因为网络中断、模型切换或会话恢复而需要从断点继续。先检查当前线程中最近一次已完成的阶段：

- 如果上一轮只完成了分析、提问或宫格生图提示词，继续完成尚未完成的下一步。
- 如果上一轮已经生成宫格图但尚未等待验收，继续停在验收点，不提前输出视频双版本。
- 如果上一轮已经输出完整 LibTV 版和即梦网页版，短语“继续”不触发第二次完整双版本交付；只回复已完成并说明可继续处理具体修改，或询问用户是否需要重发。
- 如果只完成其中一个平台版本，只补另一个缺失版本，并保持两版正文一致。
- 如果上一轮出现“流式响应中断”“响应解码失败”或类似网络错误，先把对话中已经可见的标题、段落和代码块视为已发送内容；只从最后一个可识别的断点继续，不能从头重贴整段长提示词。若无法可靠识别断点，先用一句话说明已发送到哪一部分，再询问用户是否需要重发完整版本。
- 用户明确提出“重发完整提示词”“重新生成”“按新修改生成”“把两版再贴一次”等请求，才重新输出受影响的完整版本。
- 用户明确要求单版时，只补或重发指定平台版本。

“确认”要结合当前阶段判断：确认宫格图表示进入视频提示词阶段；确认比例或分辨率表示可以进入生图阶段；如果完整双版本已经存在，单独的“确认”不应复制双版本。

## 流式响应安全

- 长提示词按较短、语义完整的段落输出；不要在同一轮反复发送相同的进度说明或整段正文。
- 工具读取、分析和最终交付各只执行一次；没有新的用户修改时，不重复读取并重写同一份完整成品。
- “继续”不能作为重试整轮输出的理由；它只恢复未完成步骤。

## LibTV 视频生成入口

双版本提示词交付完成后，追加一句简短询问：“是否使用 LibTV 生成视频？”不要在同一轮直接生成，也不要默认进入 LibTV。

- 用户选择“否”或暂不生成：结束本轮，保留已交付的 LibTV 版和即梦网页版。
- 用户选择“是”：读取[LibTV 视频生成适配](adapters/libtv-video-generation.md)，调用[视频生成流程控制器](flow/video-generation-controller.md)的 `discover-profiles`。每个选项显示 profile id、账号摘要、套餐标签和“剩余积分：暂不可读取”（除非 CLI/API 明确返回余额）。
- 用户选定 profile 后，控制器用该 profile 的 `LIBTV_CONFIG_DIR` 调用 `list-projects`。优先使用已确认的 DH folderId；没有时询问并暂停。项目按更新时间倒序展示最近 6 个，必须按精确 UUID 选择。
- 项目选定后，控制器调用 `resolve-assets`、`list-models`，只读取用户选中模型的 schema。模型、模式、比例、分辨率、时长和其他必填字段由 schema 动态生成。
- 参数完成后，控制器调用 `validate-plan`，展示项目、模型、模式、比例、分辨率、时长、LibTV 版 prompt 和真实素材节点摘要，等待最终确认。
- 用户确认后，控制器创建唯一视频节点并只触发一次 CLI `--run`。不使用远程 MCP OAuth 假装切换 profile；不把 `{{Mixed N}}` 当作节点 ID。
- 新模型自动进入列表；无法解析的必填字段严格拦截，不猜默认值、不自动替换模型或参数。
- 控制器把 run 状态保存到 `%USERPROFILE%\\.seedance-director\\video-runs`，缓存仍放在 `%USERPROFILE%\\.seedance-director\\video-flow\\cache`。用户说“继续”时只调用 `status` / `resume` 查询原节点，不重复提交。

如果宿主支持右侧视频生成控制面板，双版本交付后调用 `prepare_video_config`，一次加载平台、账号、项目、模型和全部参数选项。面板完成选择后调用 `validate_video_config`，用户点击“确认并生成”才调用 `submit_video_config`。面板提交后，用户说“继续”只调用 `resume_video_config`。

## 即梦 CLI 视频生成入口

双版本提示词完成后，先让用户在 LibTV 与即梦 CLI 中选择一个平台。选择即梦 CLI 后再选择：

- **即梦画布**：按项目、节点、实时模型 schema 和 `operationRef` 运行 `dreamina-canvas.exe`；
- **即梦对话**：按对话 session、积分、子命令帮助和 `submit_id` 运行 `dreamina.exe`。

两条路径不能混用项目、session、参数或恢复身份。每个新任务只选择一次账号，同一任务继续沿用原账号；第一版不同时提交两个平台。

控制器 `tools/dreamina_video_flow.ps1` 在最终确认前只做账号、容器、素材和参数查询。画布展示最近 6 个“即梦画布项目”；对话展示最近 6 个“即梦对话会话”。未确认不提交，用户说“继续”只查询原 `operationRef` 或 `submit_id`。

如果宿主支持右侧视频生成控制面板，优先通过 `prepare_video_config` 批量读取即梦账号、项目/会话、素材、模型和参数；不要逐项重复询问。用户修改平台、适配器、账号或模型时，只刷新受影响字段。

默认固定输出两个版本，顺序不可交换：

### LibTV 版

使用标题“LibTV 版”，下面放一个独立代码块。代码块内只包含完整、可直接复制的提示词正文；素材按提供顺序固定使用 `{{Mixed 1}}`、`{{Mixed 2}}`、`{{Mixed 3}}` 等原样占位符。编号和精确写法遵守[平台适配](adapters/platforms.md)，不再要求用户重复确认引用约定。代码块外不写说明、序号或复制提示。

### 即梦网页版

使用标题“即梦网页版”，下面放一个独立代码块。代码块内只包含与 LibTV 版内容完全一致的提示词正文，只将素材引用替换为用户确认的即梦标签或文件名格式，例如 `@图片1`。代码块外不写说明、序号或复制提示。

两版必须同时存在，且每版使用独立代码块。除素材引用格式外，两版的段落顺序、动作、台词、标点、时序和约束必须一致。没有素材时，两版正文可以完全相同，但仍保留两个标题和两个代码块。

只有用户明确说“只要 LibTV 版”或“只要即梦网页版”时，才输出单版；用户明确要求“重新生成”“修改提示词”且确实改变了成品时，继续输出受影响的完整版本。讨论阶段存在关键待决问题时可以先提问，不先输出依赖未决方向的两版成品。

宫格图已被用户确认后，视频双版本仍遵守本文件和[平台适配](adapters/platforms.md)的规则。宫格图只作为镜头规划参考；需要严格保持单格姿势、首尾构图或道具位置时，说明需要对应单格裁切图或关键帧。

按实际需要组织：精简全局目标 → 素材及用途 → 关键视角/机位 → 初始状态 → 连续动作和必要镜头变化 → 结束状态 → 台词与声音。空项省略，不机械输出“无”。不添加固定冗长 GlobalSetting 段。

素材编号可与正文一体表述；必要设置建议放正文外。用户要求“只要正文”时，仍保留两版标题和代码块，因为它们是交付格式的一部分；省略额外解释，但尚未解决的关键冲突仍先询问。

开放补全后，如果新增了影响理解的但已获授权的情节选择，在正文外用一句话说明，便于继续改。普通伸手、停步等动作不逐条报告。

局部修改后重新整合完整正文。双平台输出使用 [同一正文的引用适配](adapters/platforms.md)，不分别重新创作。

终稿表达确定的画面；选择分支、未决假设、素材准备建议和内部检查不混入正文。不堆叠英文词串、摄影器材名和无法验证的画质承诺。
